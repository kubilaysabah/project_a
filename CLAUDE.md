## What this project is

**Working title: "project_a" — THE FINAL NAME IS NOT DECIDED YET (see "Name decision" below).**

A first-person **anomaly-loop horror** game ("The Exit 8" formula) set in a 1994 Turkish apartment building ("Huzur Apartmanı"). The player is the building's night janitor (kapıcı): climb floor by floor collecting trash bags; every landing is identical; if the landing is NORMAL continue up, if there is an ANOMALY turn back; a wrong call resets you to floor 1; reach floor 8 without a mistake → rooftop → morning → ending twist (the building is seen from outside to have NINE floors).

- **Goal:** ship on Steam in 2-3 months at $4.99. This is Şahan's quick-ship title (GAME #2 in the Moguls two-developer split — Moguls' CLAUDE.md explicitly does NOT track this project; this repo is its own board and memory).
- **Full concept document:** the user's `KAPICI-oyun-fikri.txt` (kept outside the repo); its content is summarized in this file and in the GitHub issues.
- **Engine:** Unity 6.5 (6000.5.5f1), URP (URP template with PC/Mobile render pipeline assets), new Input System. Project lives at the repo root. Each developer's local clone path, hardware and personal preferences live in that developer's own **`CLAUDE.local.md`** (gitignored, auto-loaded by Claude Code) — never in this file.

## Architecture decisions (agreed, mirrors Moguls principles)

- **Interactions go through the `IEtkilesimli` contract; never write object-specific code on the player.** Şahan's request, 2026-09-22. An object exposes `Ipucu` ("TOPLA"), `EtkilesimeAcik` and `Etkilesim(oyuncu)`; `Etkilesimci` on the player aims, shows a floating "TOPLA (E)" panel above the target and calls it, knowing nothing about what the object is. Future pickups, bells, notes and the roof door sign the same contract and need no player-side change — the same principle as the anomaly cards. The prompt is **one** object moved from target to target, with a dark panel behind bold light text so it reads on both a white graybox and a dark finished scene, and its collider is **deleted** or the player's aim ray hits its own prompt.

- **An unfinished task on the landing is a mistake.** Şahan's decision, 2026-09-22: leaving a floor without collecting the trash counts as a wrong call. `KatSayaci.KararVer` takes a `gorevEksik` flag and knows nothing about what the task was, so new tasks only extend `KatYoneticisi.ToplanmamisGorevVar`. One exception is deliberate: **no task is required on an anomaly floor** (fleeing is the correct behaviour there, and forcing the janitor to tidy a dangerous landing is bad design). Since #23 the check reads the **plan** (`CopPlani`), not the scene: a floor's task is "every bag the plan drew for this floor has been collected", whatever floor the landing happens to be showing at that moment.

- **Trash bags are random and remembered.** Şahan's decision, 2026-09-23: each flat has 0-3 bags (`Kapi_N/Copler/Poset_1..3`, largest first), drawn per floor by `Assets/Scripts/Cekirdek/CopPlani.cs` with its own seed, fixed for the whole run, redrawn only after a penalty. Collected bags are recorded in the plan before a landing switches floors, otherwise the single landing would bring them back. **No anomaly card may target a bag** — the player cannot know how many there should be, and a card hiding a bag the plan already hid changes nothing, so an anomaly floor would look normal. `AnomaliButunlukTestleri` enforces it.

- **Props are Blender-scripted and placed by name.** #24 (2026-09-23). Each prop is a Python script in `Art/Blender/scripts/` run headless (`blender -b --factory-startup --python <script>.py`); shared helpers are in `ortak.py`. Sources go to `Art/Blender/*.blend`, Unity files to `Assets/Models/Props/*.fbx` (both LFS). The FBX export maps Blender (x, y, z) to Unity (−x, z, −y), so **every model's front faces +Z in Unity**; placement rotates about Y only. `GrayboxKurucu.Model` copies a model part's mesh into a GameObject carrying the **same name and path the anomaly cards target** (never drop the FBX in as-is: its root would add a path level) and falls back to the old box if the FBX is missing. Props that must be absent on a normal floor (tube, newspaper, lone shoe) are built **inactive** so a card can reveal them with data only. Hinged parts keep their pivot on the hinge; for the meter lid, like the flat doors, a **positive** Y angle opens outward. Always select an object before `origin_set`, and apply rotation before scaling a rotated primitive — both failed silently once.

- **Art direction is A (realistic PBR).** Şahan's decision, 2026-09-23 (#9): Soviet Modular Apartment Kit ($30) + Abandoned Stairwell ($19.99) proposed, purchase waits for Kubilay's budget OK and the licence question; see `Docs/asset-shopping-list.md`.

- **The stairwell is a half-turn square core and floors are stacked.** Şahan's decision, 2026-09-23 (#23). Two flights of 8 steps per floor with a 180° turn on a mid-landing at +1.5 m and an 80 cm well between the flights; landing 7 × 5 m with four flats. Because every landing is directly above the previous one, the loop teleport is **purely vertical** (−3 m at y ≥ 2.906, +3 m at y ≤ −0.6). Fake floors (3 below A, 2 above B) plus dark linear fog (8 → 17 m) exist only so the well view never shows the end of the scene. **No lamp casts shadows**: the loop requires every floor to be lit identically, and a mix of shadowed and unshadowed point lights leaks light through slabs differently per floor. Real lighting is #10's job.

- **What a landing shows is derived, never pushed.** `KatYoneticisi` runs in `LateUpdate` with `[DefaultExecutionOrder(100)]`, i.e. after `SonsuzMerdiven`, so on the frame the player reaches B they are teleported first and the decision and landing refresh happen in the same frame — the first rendered image is already the new floor. Each landing's floor is computed from its distance to the last decision point: **at the decision point it shows N, one above or below shows N+1** (a correct call in either direction is progress). This is what keeps a turn-back after a downward teleport from swapping a landing in view; do not replace it with "refresh on decision". The progress tracker is created only once the player has **settled** (grounded and not moving between two frames) — `isGrounded` alone is stale after the penalty reset and made every decision fire a step late.

- **Doors open INWARD, and a POSITIVE Y angle on `Kapi_*/Mentese` is what opens them.** Şahan's correction, 2026-09-22: they were swinging into the corridor, which no real apartment door does and which would block the stairwell. The hinges are deliberately **mirrored** (right-wall doors hinged at their −z edge, left-wall doors at their +z edge) precisely so one sign works for both; if they shared a side, every card author would have to remember which sign belongs to which door and a corridor-opening door would eventually slip through. Behind each doorway sits `Daire_Ici`, a sealed 1.2 m hall of five boxes using the shared dark material `Assets/Materials/Daire_Karanlik.mat` — without it an ajar door shows the void, and ambient skylight makes plain white boxes too bright to read as "inside". No flat interior beyond that hall is modelled or planned.

- **Door numbers stay tied to the floor counter. DO NOT "fix" this.** Şahan's decision, 2026-09-21, after testing it deliberately. Each landing's four doors show `4N-3 … 4N` for floor N (two doors until #23 changed the landing to four flats), and the upper landing shows floor N+1. Because turning back on an anomaly floor counts as progress, the numbers rise while the player physically walks *down*, which looks contradictory at first glance. Şahan checked this specifically, understood the rule behind it and chose to keep it. Claude previously proposed making the numbers fixed per landing; that proposal was considered and **declined**. Reopen the question only if Şahan raises it.

- **Game logic in plain C# classes**, separate from MonoBehaviours, for testability.
- **CONTENT IS DATA:** every anomaly is a ScriptableObject card (`AnomalyCard`: id, tier, difficulty, what it changes on the landing). The landing is built/reset from data; adding anomaly #47 must require ZERO new code, only a new asset. This is the whole game — one landing + stair loop modeled once, 60+ data-driven variations.
- Single modeled space: one landing + one stair flight, looped (player repositioned seamlessly). No open world, no walking nav beyond the loop.
- Anomaly tiers from the concept: **FISILTI** (subtle: reversed door number, changed doormat, single slipper), **TEKİNSİZ** (green bulb, door ajar, moving trash bag, wrong shadow), **KÂBUS** (rare scripted clips: figure at corridor end, all doors same number, bell rings by itself).
- **Sound is the cheapest, strongest horror tool:** normal ambience texture (distant TV, baby crying, pipe knocks) that CORRUPTS on anomaly floors (crying plays reversed, murmur goes silent). Ears notice before eyes.
- Wrong-call penalty is DELAYED, not instant: half a flight up, lights die one by one — that silence is the scariest moment. Design for it.
- Budget principle: free tools + total asset spend ≤ $100 (apartment/retro interior pack $15-30, Turkish identity via textures + ~10 small Blender props: tüp, terlik, ayakkabılık).
